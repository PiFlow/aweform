The CLI refuses physical execution pending the separately required fresh decision after exact-source review.

## Safety mechanics

The public entry point takes no child command. Its fixed child is an internal model-free plumbing worker. Child output is consumed by a separate reader thread into a bounded queue (8 records, each at most 64 KiB); oversized lines and queue overflow stop the child and produce a receipt. The supervising process polls a monotonic deadline independently of reader progress, so a silent child cannot block deadline enforcement. Aggregate CPU accounting combines supervisor process CPU, live worker CPU, and reaped-child CPU (including metric helper subprocesses); observed RSS high-water is recorded. On normal completion or any stop, the parent drains queued bytes through EOF, terminates/reaps as needed, and runs plan validation before writing the final receipt. A validation failure is itself recorded as STOP with the durable event watermark, rather than leaving a misleading successful receipt. It fsyncs the append-only event journal, then atomically writes/fsyncs `STOP.json` plus detached `STOP.sha256`. The receipt's top-level `last_durable` names flushed byte count, event sequence, and SHA-256; it never replaces or weakens event custody.

Limits apply to the complete event file plus STOP receipt and detached hash (2 MiB), 10,000 events, 120 seconds wall, 120 seconds aggregate CPU, and observed RSS 256 MiB. Unavailable CPU/RSS measurements fail closed. Events are sequence-numbered and individually flushed before advancing the durable watermark. Output directories are one-shot.

Tests use only local subprocess plumbing and synthetic events. They do not import/step Pymunk, call an A2 case, or execute a physics transition. No Stage C run is authorized by this candidate.
