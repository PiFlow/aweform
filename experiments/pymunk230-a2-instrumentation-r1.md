## Safety mechanics

The normal CLI takes no child command and supervises only the internal model-free plumbing worker; the separate fixed A2 supervisor API takes no caller-supplied command and is guarded by the exact-HEAD GO check. A2 outputs must be outside the clean candidate tree. Child output is consumed by a separate reader into a bounded 128-record queue (at most 8 MiB at the 64 KiB line cap); this admits the prescribed 61/113/66-record bursts while a reader flood beyond capacity remains a STOP. The parent drains all currently queued records with deadline checks and samples metrics on a separate 250 ms cadence, rather than spawning `ps` for every row. Bounded queue/line/event/output limits and synthetic flood/no-newline probes prevent stdout from controlling parent memory or deadlines. `ps` sampling has a 0.5 s subprocess timeout and sums the isolated live process group; Linux samples `/proc` group members. Cleanup reaps an exited leader after Darwin `EPERM`, distinguishes a stale group from a still-observed or inaccessible group, reports cleanup status/uncertainty, and never lets a cleanup exception bypass receipt creation; TERM/KILL, child wait, and EOF-reader join are bounded. Invalid merged stderr/stdout is a STOP with error type and line digest in the receipt, not a false event. Aggregate CPU is parent plus sampled live process-group usage and reaped direct-child usage; sampling can miss short-lived descendants and is not hard aggregate enforcement. RSS adds parent high-water RSS to sampled live group RSS; this is observed platform-dependent STOP measurement, not hard aggregate memory enforcement. The exact accounting limitations are embedded in the receipt. On normal completion or any stop, the parent drains queued records and validates output before the hashed STOP receipt. Journal writes are fsynced before advancing the sequence/hash watermark; a write/fsync exception truncates back to the last complete offset. The hashed receipt is atomically written/fsynced and shares the 2 MiB inclusive cap with journal bytes, with 4 KiB reserved. A validation failure remains STOP with the durable watermark, not a misleading successful receipt.

Limits apply to the complete event file plus STOP receipt and detached hash (2 MiB), 10,000 events, 120 seconds wall, 120 seconds aggregate CPU, and observed RSS 256 MiB. Unavailable CPU/RSS measurements fail closed. Events are sequence-numbered and individually flushed before advancing the durable watermark. Output directories are one-shot.

Tests use only local subprocess plumbing, exact file hashing, fake `Space` objects, and synthetic diagnostic streams/workers. They do not import/step Pymunk, call an A2 case, or execute a physics transition. The actual child, its Pymunk step wrapper, and the guarded supervisor route remain unexercised. No Stage C run is authorized by this candidate; future use requires a separate Flow GO against the exact independently reviewed HEAD.
