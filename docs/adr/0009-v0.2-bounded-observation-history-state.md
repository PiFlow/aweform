# ADR 0009 — V0.2 Opens: Bounded One-Step Observation-History State

**Status:** Accepted

**Authorisation:** Flow, 2026-08-24, Buzz Aweform channel. Flow directed the
reusable category form over the single-variable form, and directed that the
authorisation open a new stage rather than edit ADR 0001.

The specific bounds are not Flow's rulings and should not be attributed to
them. The budget of one (Section C) is the value independent review defaulted
to after rejecting an unsupported budget of two; Flow may set it otherwise.
Conditions B.4 and B.5 originate from independent review, not from this
document's author, as does the observation-write/clear split in B.2 and B.3.

**Opens:** V0.2. **References, and does not amend,** ADR 0001.

## Context

ADR 0001 lists "memory" among V0.1's non-goals, and immediately adds: "These
are not rejected permanently. They are deferred until a later developmental
problem justifies them." That sentence is the mechanism this ADR uses. ADR
0001 does not need to be edited, and is not edited: it remains the accurate
record of the V0.1 scope covering EXP-000 through EXP-003, whose statuses
differ: EXP-000 and EXP-001 have completed evidence, EXP-002 calibration is
complete but its confirmation is unexecuted, and EXP-003 is development-only.

### What V0.1's "no memory" actually meant

It did not mean the organism retained nothing between decisions, and this ADR
must not be read as claiming it did. The V0.1 controllers already retain state
that persists across decisions and determines actions, including state that
depends on past observations — `_mode` is held across steps because of a past
energy reading. The inventory is in "Pre-existing retained state" below.

The real V0.1 boundary was narrower: **no controller added an
observation-history value of its own to the causal action path, and nothing
was learned.** That is the boundary this ADR moves, and it is the only one it
moves.

### The developmental problem that justifies moving it

Development on the localized-charging environment produced
`StationB50TrendController` (`STATION_B50_TREND`), which retains one scalar
between decisions — the previous EXPLORE decision's maximum visible beacon
value — and uses it for a single anticipatory guard: a strictly weakening
beacon trend at moderate energy enters SEEK earlier than the fixed energy
threshold alone would.

**This is memory**, in the ordinary technical sense: a value derived from a
previous observation is stored and changes a later action. Its footprint is
one float and one step. Calling it "temporal state" would be an implementation
label standing in for an authorisation, and this ADR does not do that.

The roadmap's EXP-004 asks whether closed-loop control gains value under
environmental change. A controller that can condition on a *change* in its
input rather than only its *level* **enables** the key secondary comparison
there — whether one-step beacon history gains relative value under relocation
beyond what plain energy feedback already provides. It is not required for
EXP-004: the roadmap states that if the trend controller is not merged in
time, EXP-004 proceeds with `STATION_B50` and the station-compatible
regulator, and the primary comparison does not involve the trend controller at
all.

## Decision

### A. V0.2 is opened, and V0.1 is not closed

V0.2 is a **project permission boundary**, not a new organism, substrate, or
codebase. The body, environment, observation/action contract, energy costs,
viability thresholds, and termination rules are unchanged; ADRs 0002–0008
carry forward in full.

V0.2 differs from V0.1 in exactly one respect: controllers may add bounded
one-step observation-history state to the causal action path, under Section B.
Nothing else about V0.1's non-goals is claimed, and each remaining entry in
ADR 0001's non-goal list still requires its own deferral-claiming ADR.

Opening V0.2 does not complete, close, or discharge V0.1. EXP-002's
confirmatory execution remains specified-but-unexecuted on untouched seeds
`50001–51000`, and that obligation is unaffected by this ADR.

**Stage labels attach to experiments, not to controller arms.** EXP-004 is a
V0.2 experiment whose planned primary comparison uses `STATION_B50` and the
station-compatible energy-blind regulator. If the trend controller is
independently approved and merged in time, `STATION_B50_TREND` may be included
as an optional third arm; otherwise the experiment proceeds with the two-arm
comparison. Any no-memory arm remains a control, exactly as EXP-000's
energy-blind ablation was a control. Reports must not describe `STATION_B50` as
"the V0.1 controller" and `STATION_B50_TREND` as "the V0.2 controller"; doing
so would turn a control arm into a cross-stage comparison that was never run.

### B. The authorised category

**Bounded one-step observation-history state (BOHS).**

The conditions below are derived from the decision trace of the only
implemented mechanism, not asserted independently of it. Five successive
drafts stated a general rule and were then falsified by a branch the real
controller takes; the trace comes first here so the rule is checked against
the mechanism by construction.

#### B.0 Reference trace

`StationB50TrendController.__init__()`, `.act()`, and `.reset()` in
`src/aweform/exp003.py` as present at the exact PR #38 tree
`6b069f64bf239e3260ec7ae5a31979c6d85ec297`. `P` is
`_previous_explore_beacon_max`. The EXPLORE entry reads `P` into
`previous_max` before evaluating any guard; E2 additionally uses that
snapshot in the anticipatory guard. The table records both the local mode
transition and the same-call suffix where EXPLORE falls through into SEEK.

| Path | Mode in | Reads relevant to `P` and transition | `P` operation | Mode transition / action |
|---|---|---|---|---|
| `init` | construction | none | set `None` | initial mode `EXPLORE` |
| `invalid-input` | any | input type only | none | raises `ValueError`; mode and `P` unchanged |
| `E1 → S1` | `EXPLORE` | current beacon triple, `P` snapshot, energy; charging contact | clear | `EXPLORE → SEEK → CHARGE`; `WAIT` |
| `E1 → S2` | `EXPLORE` | current beacon triple, `P` snapshot, energy; charging contact | clear | `EXPLORE → SEEK`; local SEEK action |
| `E2 → S1` | `EXPLORE` | current beacon triple, `P` snapshot, energy, trend thresholds, prior-value comparison; charging contact | clear | `EXPLORE → SEEK → CHARGE`; `WAIT` |
| `E2 → S2` | `EXPLORE` | current beacon triple, `P` snapshot, energy, trend thresholds, prior-value comparison; charging contact | clear | `EXPLORE → SEEK`; local SEEK action |
| `E3` | `EXPLORE` | current beacon triple, `P` snapshot, energy and trend guards | write `max(L,F,R)` | remains `EXPLORE`; EXPLORE action |
| `S1` | `SEEK` | charging contact | none | `SEEK → CHARGE`; `WAIT` |
| `S2` | `SEEK` | charging contact and L/F/R beacon | none | remains `SEEK`; local SEEK action |
| `C1` | `CHARGE` | charging contact | none | `CHARGE → SEEK`; local SEEK action |
| `C2` | `CHARGE` | charging contact, energy, construction-invariant `config.recover` | clear | `CHARGE → EXPLORE`; EXPLORE action |
| `C3` | `CHARGE` | charging contact, energy/recovery threshold | none | remains `CHARGE`; `WAIT` |
| `reset` | any | none for `P` | clear | mode `EXPLORE`; explorer segment reset |

Three facts follow from the table, and the conditions are written to permit
exactly these and no more:

- **Two kinds of write exist.** One observation write (`E3`) and five
  initialization/clearing writes (`init`, `E1`, `E2`, `C2`, `reset`). A rule
  requiring every write to be observation-derived makes the mandatory clears
  illegal.
- **`P` is read on every EXPLORE path, but never to compute the value written.**
  E2 uses the snapshot to choose SEEK-and-clear; E3 applies one fixed function
  to the current observation. A rule forbidding all reads of retained state by
  a writing branch excludes this controller, which is also `_mode`-gated
  throughout.
- **`P` is non-`None` only at the start of an EXPLORE decision immediately
  following `E3`.** Only `E3` writes a value; `E1`/`E2` clear and leave
  EXPLORE; `C2`/`reset` clear on entering EXPLORE; `S1`/`S2`/`C1`/`C3` never
  touch `P` and are reachable only with `P` already `None`.

#### Conditions

1. **Type.** Each field is a single `float | None` in a named instance
   attribute. No containers, arrays, dataclasses, objects, or strings. `int`
   is not permitted — Python integers are arbitrary-precision, unlike the
   IEEE-754 double the observation contract uses — and `bool` is not
   permitted, both as an `int` subclass and because it makes type checks
   ambiguous. Admitting a further type requires an amending ADR.
2. **Observation writes.** A write of a non-`None` value applies **one fixed
   declared function to the current observation alone**: a copy of one
   controller-visible component, or a `min`/`max`/single-element selection
   over components of that one observation. No arithmetic combination — no
   sums, differences, products, weighted averages, exponential smoothing,
   counters, encodings, or bit packing. The function is a constant of the
   controller: it is applied unconditionally wherever an observation write
   occurs, and neither the function nor its inputs may vary with any retained
   state. (`E3`.)
3. **Clears.** The only other permitted write is `None`, and every `None`
   write occurs at an initialization or clearing point registered under
   Section D. Clears are not observation-derived and are not required to be.
   (`init`, `E1`, `E2`, `C2`, `reset`.)
4. **Reads.** A BOHS field may be read by its own controller's action
   selection, by guard conditions that determine a mode transition or a
   registered clear, and by diagnostic records that no action-selection branch
   reads. It may **not** be read to determine the value written by an
   observation write, or to select among candidate functions or components for
   one. No BOHS field may read any other BOHS field for any purpose.

   The last clause is what closes cross-coupling. Over components taking
   values in `{0, 1}`, field A choosing which component to copy based on B's
   prior value while B chooses based on A's preserves bits indefinitely, with
   every individual write remaining a legal one-observation selection. The
   budget of one makes this unreachable today; the clause is stated because it
   must already hold before the budget can ever be raised.
5. **Presence and read barrier.** Whether a field is `None` is the
   availability sentinel for the immediately preceding observation write, not
   an additional branch result. Every decision path must either write a fresh
   current-observation value or perform a registered clear, except a path
   proven to enter with the field already `None` and neither read nor write it.
   A guard may test `None` only to determine whether that immediately preceding
   value exists. If **any retained causal state** — BOHS or inherited state
   such as `_mode` or an explorer counter — influences whether the current
   decision clears the field or performs a fresh observation write, the field
   enters a read barrier. No later controller path may read that field while
   the barrier is set. The barrier resets only after a fresh current-
   observation write, or after a registered write/clear whose own operation
   predicate and value are selected at that operation point from the current
   observation and fixed constants without reading or depending on any
   retained state or the prior field value. A construction-invariant
   configuration value is exempt from that phrase only when it was initialized
   before the first `act()` call, its underlying value is immutable for the run,
   its controller-visible binding is read-only after initialization (or the
   action path uses an immutable snapshot), it is independent of observations
   and history, and it cannot encode a branch bit; the check must verify all
   five properties. A frozen configuration object alone does not freeze a
   controller attribute that can be rebound. Mutable or
   observation/history-dependent inherited state — including `_mode`, counters,
   RNG state, and mutable configuration or bindings — is never exempt.
   `reset()` and episode start also reset the barrier. A later clear reached
   through a retained-state-dependent mode transition may reset the barrier
   only if it dominates every subsequent BOHS read on that barriered path (or
   reset/episode end intervenes); a local current-observation/config predicate
   is not sufficient. This barrier prevents a later `None`-versus-value read
   from recovering the older branch bit. In the reference trace `P` is
   non-`None` only after `E3`; all other paths either clear it or are proven to
   enter with `P` as `None`.
6. **No carry-over.** No control path leaves a value written before the
   immediately preceding decision in place. In the reference trace every
   EXPLORE decision either overwrites `P` with a fresh current-observation
   value or clears it, and `P` is provably `None` in every non-EXPLORE branch.
   This is what makes "one step" a property of the controller rather than of
   an individual assignment.
7. **Update cadence.** At most one write to each BOHS field per `act()` call —
   counting an observation write and a clear alike — on the controller's own
   decision path. No writes from outside the controller.
8. **Lifetime.** Cleared by `reset()` and by every registered clearing point.
   Never survives a `reset()`, an episode, a seed, or a run. Clearing points
   are part of the frozen scientific contract of any experiment using the
   controller: changing one changes the controller and invalidates prior
   characterization.
9. **Not learned.** No update rule adjusts any threshold or parameter from
   experience, and no threshold is a function of any BOHS value. Every
   BOHS-specific threshold is a `Final` constant declared in source. This does
   not claim every threshold in the controller is `Final`: the inherited
   `EXP003ControllerConfig` fields are configurable dataclass parameters, set
   once at construction and never adjusted from experience.
10. **Provenance.** Derived solely from the controller's own observation
    contract as fixed by ADR 0002 and ADR 0008. No evaluator-only quantity, no
    privileged simulator state, no body position, heading, or coordinates.

#### Conformance of the reference mechanism

Each condition is checked against the B.0 table rather than against the PR
description. The intended declared type for `P` is `float | None`, but the
pinned PR #38 tree is **not yet conforming to B.1**: its
`BeaconObservation` validation accepts integer and boolean L/F/R values, and
`max(observation.beacon.as_tuple())` can preserve that type into the E3
assignment. PR #38 must enforce built-in floats at the `BeaconObservation`
boundary, and add adversarial integer/boolean tests, before this reference
mechanism can be called conformant. Only E3 writes a value, always `max` over
the current beacon triple, never varying (B.2). `init`, `E1`, `E2`,
`C2`, and `reset` are the five registered initialization/clearing points
(B.3). Every EXPLORE path reads a snapshot of `P`, but no read selects the
function or input components used by the observation write; E2 uses the
snapshot only for its registered transition-and-clear guard (B.4). Because
E2's prior-`P` guard can choose clear versus E3's fresh write, its clear path
is barriered under the retained-state rule: the subsequent S/C paths do not
read `P`, and C2 is a registered clear whose own predicate uses current
contact, current energy, and the construction-invariant `config.recover`.
That exemption is conditional on the controller-visible `config` binding being
read-only after initialization or on the action path using an immutable
snapshot; the frozen dataclass alone is insufficient. The pinned PR #38 tree
must enforce or reject this condition before the trace can be called
conformant.
Although retained `_mode` controls reachability of C2, C2 (or `reset()`/
episode end) must dominate every subsequent `P` read on the barriered path;
the exhaustive check must prove that dominance rather than infer independence
from C2's local predicate. No `P` read occurs between E2 and C2. The E3 path
itself performs
the fresh observation write before any later read. Invalid-
input rejection occurs before any controller state write and preserves the
prior mode and `P`; exhaustive BOHS decision-path checks therefore cover all
valid `StationObservation` paths plus this rejection/state-preservation path.
At construction `P` is `None`; after an `E3` path it is the immediately
preceding observation value, and every other path either clears it or is
provably entered with `P` already `None` (B.5). Every EXPLORE decision either
overwrites or clears, and `P` is provably `None` in `S1`, `S2`, `C1`, and `C3`
(B.6). No branch writes twice (B.7). Construction, `reset()`, and all
registered clearing points clear `P` (B.8). The
`0.65` and `0.10` thresholds are `Final[float]` at `exp003.py:37-38` (B.9).
The value comes from `observation.beacon.as_tuple()`, the controller-visible
contract (B.10).

This section is a claim about the branch's control-flow trace, not a claim that
the pinned PR #38 implementation currently passes every condition. It is not a
substitute for the Section D checks. The B.1 defect above was verified by
reading source; the conformance checks have not been executed.

### C. Budget

**At most one BOHS value per controller.** No limit on how many controllers
may use the category — that is what makes it a reusable category rather than a
single-mechanism exception.

One is what the only evidenced mechanism uses. An earlier draft of this ADR
set the budget at two, on the reasoning that it would let a second feature
land without an ADR cycle. That was unsupported scope: avoiding future process
is not a scientific reason to authorise unreviewed state, and independent
review was right to reject it. A second BOHS value gets its own amending ADR
and its own review, which is the same friction every other stateful controller
faces.

Condition B.4 remains stated in full even though a budget of one makes
cross-field coupling impossible today. It is the condition that has to hold
before the budget can ever be raised, and it must not have to be rediscovered
at that point.

Raising the budget requires a new amending ADR, not an edit to this one.

Diagnostic-only records do not consume budget (Section E).

### D. Registration and enforcement

**No controller carrying BOHS may merge, and no formal, calibration, or
confirmatory seeds may be run with one, until the registry exists and the
checks below pass.** This gate is deliberately earlier than an earlier
draft's, which deferred enforcement to first confirmation and would have
allowed unregistered BOHS controllers into `main` in the meantime.

**Registry.** A single manifest at `docs/adr/0009-bohs-registry.md`. It
classifies **all retained action-relevant and diagnostic state of every
controller it covers**, not only BOHS fields — a registry with rows for BOHS
alone cannot express that `_last_decision` is diagnostic-only, which is
precisely the claim Section E depends on. It includes retained root objects
and their nested action state, while transient locals are not fields. Each
controller additionally declares its own entries in source as a class
attribute; the manifest is the union of those declarations.

Every row carries: controller class; attribute name; **classification**; and
the fields required by that classification.

- **`bohs`** — an authorised observation-history field. Requires: declared
  type; the fixed observation function of B.2; every registered clearing
  point; the complete reader set; budget consumption (always 1).
- **`causal-inherited`** — retained state on the action path that this ADR
  does not authorise and does not modify. Requires: the source that does
  govern it. `config`, `explorer`, `_mode`, the explorer segment counters, and
  `policy_rng` are these.
- **`diagnostic`** — retained state with **no action-selection reads**.
  Requires: the complete reader set, all of which must be external inspection.
  `_last_decision` is this.

**Checks.** Each is a test. Every check runs over **exhaustive branch and path
coverage of `__init__()`, `act()`, and `reset()`**, not merely over decisions an
experiment happens to exercise — a rule that holds on sampled trajectories and
fails on an unexercised branch is not a bound.

- *Registration completeness* — every retained action-relevant or diagnostic
  attribute of a covered controller appears in the manifest with a
  classification, **including inherited action-causal fields and nested state**,
  not only attributes added beyond a base class; and every manifest row names an
  attribute or declared nested field that exists.
- *B.1* — declared type is `float | None`; the runtime value is always `float`
  or `None`.
- *B.2* — every non-`None` write equals the single declared function applied
  to that decision's observation, and no branch varies the function or its
  inputs.
- *B.3* — every `None` write occurs at a registered clearing point, and every
  registered clearing point is reachable.
- *B.4* — retained state does not determine an observation-write's value,
  function, or input components; no BOHS field is read by any other BOHS
  field.
- *B.5* — every path either writes a fresh observation value, performs a
  registered clear, or is proven to enter with the field `None` and not read or
  write it; after any retained-state-dependent clear/write choice, no later
  BOHS read is permitted until a fresh observation write, reset/episode end, or
  a registered clear/write that dominates every subsequent BOHS read on that
  barriered path. That operation must be independent of retained state and the
  prior field value, subject only to the construction-invariant configuration
  exception. The exception requires all five B.5 properties above, including
  a read-only controller binding or immutable action-path snapshot. The
  exhaustive path check must verify those properties, prove the dominance
  relation regardless of retained-state-controlled reachability, and inspect
  all other inherited causal state as well as BOHS reads when identifying the
  dependency; a local clear predicate is not sufficient.
- *B.6* — no field holds a value written before the immediately preceding
  decision.
- *B.7* — at most one write to each BOHS field per `act()` call; no writer
  outside the controller.
- *B.8* — the field is `None` after `reset()` and after every registered
  clearing point.
- *B.9* — BOHS-specific thresholds are `Final`; no threshold changes across a
  run.
- *B.10* — the value is traceable to the controller's own observation contract
  only.
- *Section E* — no action-selection branch reads any attribute classified
  `diagnostic`.

**Neither the registry nor the checks exist yet.** Until both exist and pass,
the boundary in this ADR is written down, not enforced, and this document must
not be cited as evidence that it is mechanically guaranteed. Building them is
in scope for PR #38, which introduces the first BOHS controller: that PR needs
a source declaration, manifest rows classifying `_previous_explore_beacon_max`
as `bohs`, `_mode`, `config`, `explorer` and their retained nested action
state as `causal-inherited`, and `_last_decision` as `diagnostic`, plus these checks —
not only the docstring correction previously identified. It must also enforce
B.1 at the observation boundary and include adversarial integer/boolean tests
before the pinned trend controller can be treated as conformant or merged.

### E. Diagnostic-only state is outside the budget

State that exists solely to record what a controller did — a decision trace, a
counter for reporting — is outside BOHS and consumes no budget, on one
condition: **no action-selection branch reads it.** The condition is the whole
distinction. A diagnostic field that any action-selection branch reads is
causal state and consumes budget regardless of what it is named.

This carve-out is required for correctness, not convenience: PR #38 adds
`_last_decision` to the base `StationB50Controller` as instrumentation, and an
exclusion that banned all added retained state would prohibit it.

### F. Pre-existing retained state

The following already persists between decisions in
`StationB50TrendController` and its base class. This ADR neither authorises,
re-authorises, modifies, nor extends any of it; each is listed with the source
that does govern it.

- **`_mode`** (`EXPLORE`/`SEEK`/`CHARGE`) — causal, observation-dependent. The
  three-mode form including `CHARGE` is EXP-003's, governed by the EXP-003
  specification and ADR 0008. ADR 0004 governs only the earlier two-mode
  EXPLORE/SEEK_RESOURCE hysteresis it decided for EXP-000; it is not the
  authority for `CHARGE`.
- **`StochasticPersistentExplorer` segment counters**
  (`_forward_actions_remaining`, `_turn_action`, `_turn_actions_remaining`) —
  causal. The run-and-turn primitive is specified in EXP-001; ADR 0004 decided
  persistent exploration for EXP-000.
- **`config`** — construction-invariant causal configuration. Its thresholds
  and costs are governed by the EXP-003 specification and ADR 0008; this ADR
  does not make them BOHS state or authorise changing them from experience.
  A configuration value qualifies for the narrow B.5 exemption only if it was
  initialized before the first `act()`, its underlying value is immutable for
  the run, its controller-visible binding is read-only after initialization (or
  the action path uses an immutable snapshot), it is independent of
  observations/history, and it cannot encode a branch bit. The frozen
  `EXP003ControllerConfig` dataclass alone does not prove that the controller's
  `self.config` binding cannot be rebound; the Section D check must enforce or
  reject the exception on that basis.
- **`explorer`** — the retained EXP-001 run-and-turn primitive. Its nested
  counters and RNG are causal and governed by EXP-001 and ADR 0004; this ADR
  does not authorise or modify them.
- **`policy_rng`** — causal. A `np.random.Generator` whose bit-generator state
  advances on every run-length sample inside `explorer`. It is the largest
  retained object in the controller and is governed by the experiments' seed
  and RNG-stream conventions.
- **`_last_decision`** — diagnostic only, no action-selection reads. It is
  **not** pre-existing merged state: `EXP003ControllerDecision` and
  `_last_decision` are absent from `src/aweform/exp003.py` at base `44f44d4`
  and are introduced by PR #38. It is listed here as retained state of the
  controller under review, not as inherited state, and it is outside the
  budget under Section E.

### G. Exclusions

Outside V0.2 and requiring their own deferral-claiming ADR:

- any additional **causal** temporal or action-path state beyond the BOHS
  budget, whether or not it is observation-derived;
- retention over more than one decision; any accumulation, integration,
  smoothing, filtering, or arithmetic combination of observations;
- any observation-write value or function/input selection that reads a BOHS
  field or other retained controller state, or any BOHS field read by another
  BOHS field — the cross-coupling channel described in B.4;
- any unregistered clear, skipped write with a non-`None` prior value, or other
  presence/carry-over path that violates B.5 or B.6;
- any BOHS read after a retained-state-dependent clear/write choice before the
  B.5 barrier is reset by a fresh observation write, reset/episode end, or an
  independent write/clear that dominates every subsequent BOHS read;
- any claimed B.5 reset based only on a local current-observation/config
  predicate when retained state controls whether the clearing path is reached;
- any state surviving `reset()`, an episode, a seed, or a run;
- learned or adaptive regulation, update rules, or experience-adjusted
  thresholds;
- episodic, spatial, or map-like memory, world models, or prediction;
- cross-episode persistence or individuality.

Learning, cross-episode persistence, spatial maps, and adaptive updates are
**not** bundled into "memory-capable". V0.2 authorises bounded within-episode
observation history and nothing else; experience-dependent regulation remains
governed by the separate learning-transition ADR named in the research
roadmap.

This ADR authorises mechanism only. It authorises no experimental claim, seed
reservation, calibration, or confirmatory run.

### H. First V0.2 experiment, and the status of existing evidence

EXP-004 is the first V0.2 experiment. Its protocol document remains unwritten
and is not fixed by this ADR.

PR #38's controller work is **disclosed preparatory development**, not V0.2
evidence, and is not retroactively relabelled by this ADR. The `18141–18180`
development batch, run under the earlier scope, remains exploratory and
disclosed as such; it cannot be promoted into calibration or confirmatory
evidence.

Reports on `STATION_B50_TREND` must describe it as a controller carrying
bounded one-step observation-history state, so that any difference against
`STATION_B50` is attributed to that addition rather than presented as an
unexplained improvement.

## Rationale

Opening a stage rather than editing ADR 0001 is the better instrument for the
reason ADR 0001 itself gives: the non-goals are deferrals, and the document
already anticipated a later problem claiming one. Editing the list in place
would have rewritten the scope record covering four experiments with mixed
statuses to authorise a fifth. The earlier draft of this ADR did exactly that,
and it was wrong.

The category form is broader than the evidence. Exactly one BOHS value exists,
in one controller; this ADR authorises a class. That is a deliberate decision
by Flow. With the budget at one, the cost is not unreviewed combinations
within a controller — those remain impossible — but that any number of future
controllers may adopt the mechanism without an individual authorisation for
each. The bounds in Section B and the registration gate in Section D exist to
make that cost bounded and visible rather than open-ended.

Conditions B.2, B.4, and B.5 do the work a count cannot, and none of them
came from this document's author. A budget of "N scalars" is not a bound on
information. An unconstrained derivation packs arbitrarily much history into
one double, which B.2 answers by fixing a single observation function. A set
of individually one-step fields is not a one-step system, because
cross-coupled selections preserve bits indefinitely while every single write
remains a legal one-observation selection; B.4 answers that. And a field's
`None`-versus-value status is itself a bit, so a conditional or skipped write
is a channel even with one field and no coupling; B.5 answers both the direct
presence case and the delayed re-read case with its barrier, including when
the clear/write choice is made by inherited causal state rather than BOHS
itself. Any one of the
three alone leaves the boundary open.

The B.0 trace is in the ADR rather than in a review comment on purpose. Five
drafts of this document stated a general condition and were then falsified by
a branch the controller actually takes — most recently a rule against reading
retained state in a writing branch, which would have excluded the `_mode`-gated
controller it exists to authorise. Deriving the conditions from an enumerated
trace makes that failure mode visible at review time instead of one round
later.

## Consequences and trade-offs

Every current-scope document that asserts V0.1 must change with this ADR, or
the repository contradicts itself. `AGENTS.md`, `README.md`, the research
roadmap, and `docs/safety-boundary.md` are updated in the same change. A
merged ADR alone cannot make the repository V0.2.

Neither the registry nor the checks exist. Until both do, the strongest true
statement is that the boundary is written down, not that it is enforced — and
because Section D gates merging rather than confirmation, building them is
blocking work for PR #38 rather than deferred work.

Adding observation-history state makes a controller harder to reason about
than one without it: behaviour depends on clearing points, so experiments must
pin the exact source revision, thresholds, clearing points, and state
semantics they inherited rather than tracking a branch.

The V0.1 boundary can be summarized as no added observation-history value of
its own on the causal action path. It should not be shortened to "V0.1 has no
memory": existing V0.1 controllers retained observation-dependent mode,
counters, and RNG state, but did not add this kind of observation-history
value or learn. That precise historical boundary is the reason for opening a
stage rather than amending one; anyone citing it should use the narrow
boundary defined in the Context above.
