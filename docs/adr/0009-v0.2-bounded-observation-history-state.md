# ADR 0009 — V0.2 Opens: Bounded One-Step Observation-History State

**Status:** Accepted

**Authorisation:** Flow, 2026-08-24, Buzz Aweform channel. Flow directed the
reusable category form over the single-variable form, and directed that the
authorisation open a new stage rather than edit ADR 0001.

The specific bounds are not Flow's rulings and should not be attributed to
them. The budget of one (Section C) is the value independent review defaulted
to after rejecting an unsupported budget of two; Flow may set it otherwise.
Conditions B.3 and B.4 originate from independent review, not from this
document's author.

**Opens:** V0.2. **References, and does not amend,** ADR 0001.

## Context

ADR 0001 lists "memory" among V0.1's non-goals, and immediately adds: "These
are not rejected permanently. They are deferred until a later developmental
problem justifies them." That sentence is the mechanism this ADR uses. ADR 0001
does not need to be edited, and is not edited: it remains the accurate record of
the stage under which EXP-000, EXP-001, EXP-002, and EXP-003 were specified and
run.

### What V0.1's "no memory" actually meant

It did not mean the organism retained nothing between decisions, and this ADR
must not be read as claiming it did. The V0.1 controllers already retain state
that persists across decisions and determines actions, including state that
depends on past observations — `_mode` is held across steps because of a past
energy reading. The inventory is in "Pre-existing retained state" below.

The real V0.1 boundary was narrower: **no controller added an
observation-history value of its own to the causal action path, and nothing was
learned.** That is the boundary this ADR moves, and it is the only one it moves.

### The developmental problem that justifies moving it

Development on the localized-charging environment produced
`StationB50TrendController` (`STATION_B50_TREND`), which retains one scalar
between decisions — the previous EXPLORE decision's maximum visible beacon
value — and uses it for a single anticipatory guard: a strictly weakening
beacon trend at moderate energy enters SEEK earlier than the fixed energy
threshold alone would.

**This is memory**, in the ordinary technical sense: a value derived from a
previous observation is stored and changes a later action. Its footprint is one
float and one step. Calling it "temporal state" would be an implementation
label standing in for an authorisation, and this ADR does not do that.

The roadmap's EXP-004 asks whether closed-loop control gains value under
environmental change. A controller that can condition on a *change* in its
input rather than only its *level* **enables** the key secondary comparison
there — whether one-step beacon history gains relative value under relocation
beyond what plain energy feedback already provides. It is not required for
EXP-004: the roadmap states that if the trend controller is not merged in time,
EXP-004 proceeds with `STATION_B50` and the station-compatible regulator, and
the primary comparison does not involve the trend controller at all.

## Decision

### A. V0.2 is opened, and V0.1 is not closed

V0.2 is a **project permission boundary**, not a new organism, substrate, or
codebase. The body, environment, observation/action contract, energy costs,
viability thresholds, and termination rules are unchanged; ADRs 0002–0008
carry forward in full.

V0.2 differs from V0.1 in exactly one respect: controllers may add bounded
one-step observation-history state to the causal action path, under Section B.
Nothing else about V0.1's non-goals is claimed, and each remaining entry in
ADR 0001's non-goal list still requires its own deferral-claiming ADR.

Opening V0.2 does not complete, close, or discharge V0.1. EXP-002's
confirmatory execution remains specified-but-unexecuted on untouched seeds
`50001–51000`, and that obligation is unaffected by this ADR.

**Stage labels attach to experiments, not to controller arms.** EXP-004 is a
V0.2 experiment in which two of three arms use no added observation-history
state. Those arms are controls, exactly as EXP-000's energy-blind ablation was
a control. Reports must not describe `STATION_B50` as "the V0.1 controller" and
`STATION_B50_TREND` as "the V0.2 controller"; doing so would turn a control arm
into a cross-stage comparison that was never run.

### B. The authorised category

**Bounded one-step observation-history state (BOHS).** A controller may retain
values meeting *every* condition below. Failing any one of them puts the state
outside this ADR and requires its own.

1. **Type.** Each value is a single `float | None`, held in a named instance
   attribute. No containers, arrays, dataclasses, objects, or strings. `int`
   is **not** permitted: Python integers are arbitrary-precision and are not
   bounded by the IEEE-754 double the rest of the observation contract uses.
   `bool` is not permitted either, both because it is a subclass of `int` and
   because admitting it would make type checks ambiguous. Admitting any
   further type requires an amending ADR.
2. **Derivation.** The value written is a fixed, declared function of the
   **current** observation alone: a direct copy of one controller-visible
   observation component, or a `min`/`max`/single-element selection over
   components of that one observation. **No arithmetic combination is
   permitted** — no sums, differences, products, weighted averages,
   exponential smoothing, counters, encodings, or bit packing. Which component
   or which function is used is a declared constant of the controller.
3. **No coupling to retained state.** Neither the value written nor the choice
   of which value to write may depend on any BOHS field — its own prior value
   or any other's — or on any other retained controller state.

   This condition is load-bearing and is not implied by condition 2. Two
   fields that each satisfy "a selection over one current observation" can
   still preserve bits indefinitely by cross-coupling: over observation
   components taking values in `{0, 1}`, field A can select which component to
   copy based on B's prior value while B selects based on A's, and the pair
   carries information forward without limit. Every individual write looks
   one-step; the system is not. The same defect appears within a single field
   whose selection rule reads its own prior value.
4. **No carry-over.** No control path may leave a previously written value in
   place for a second decision. At every decision on which a BOHS field could
   be read, it has either been overwritten with a fresh current-observation
   value or cleared. This is what makes "one step" a property of the
   controller rather than of an individual assignment.
5. **Update cadence.** At most one write per `act()` call, on the controller's
   own decision path. No writes from outside the controller.
6. **Readers.** Read only by that controller's own action selection, and by
   diagnostic records that no action-selection branch reads. Never read by the
   environment, the evaluator, or another controller.
7. **Lifetime and clearing.** Cleared by `reset()`, and by every declared
   clearing point in the controller's registration entry. Never survives a
   `reset()`, an episode, a seed, or a run. Clearing points are part of the
   frozen scientific contract of any experiment using the controller: changing
   one changes the controller and invalidates prior characterization.
8. **Not learned.** No update rule adjusts any threshold or parameter from
   experience, and no threshold is a function of any BOHS value. Every
   BOHS-specific threshold is a `Final` constant declared in source. This does
   not claim that every threshold in the controller is `Final`: the inherited
   `EXP003ControllerConfig` fields are configurable dataclass parameters, set
   once at construction and never adjusted from experience.
9. **Provenance.** Derived solely from the controller's own observation
   contract as fixed by ADR 0002 and ADR 0008. No evaluator-only quantity, no
   privileged simulator state, no body position, heading, or coordinates.

### C. Budget

**At most one BOHS value per controller.** No limit on how many controllers
may use the category — that is what makes it a reusable category rather than
a single-mechanism exception.

One is what the only evidenced mechanism uses. An earlier draft of this ADR
set the budget at two, on the reasoning that it would let a second feature
land without an ADR cycle. That was unsupported scope: avoiding future process
is not a scientific reason to authorise unreviewed state, and independent
review was right to reject it. A second BOHS value gets its own amending ADR
and its own review, which is the same friction every other stateful controller
faces.

Condition B.3 remains stated in full even though a budget of one makes
cross-field coupling impossible today. It is the condition that has to hold
before the budget can ever be raised, and it must not have to be rediscovered
at that point.

Raising the budget requires a new amending ADR, not an edit to this one.

Diagnostic-only records do not consume budget (Section E).

### D. Registration and enforcement

**No controller carrying BOHS may merge, and no formal, calibration, or
confirmatory seeds may be run with one, until the registry exists and the
checks below pass.** This gate is deliberately earlier than the previous
draft's, which deferred enforcement to first confirmation and would have
allowed unregistered BOHS controllers into `main` in the meantime.

**Registry.** A single manifest at `docs/adr/0009-bohs-registry.md`, with one
row per BOHS field and these columns: controller class; attribute name;
declared type; derivation rule; every reader; lifetime; every clearing point;
budget consumption. Each controller additionally declares its own fields in
source as a class attribute, and the manifest is the union of those
declarations.

**Checks.** Each is a test, and each maps to a condition in Section B:

- *Registration completeness* — every attribute a controller adds beyond its
  base class's retained state appears in its declared entry, and every declared
  entry names an attribute that exists.
- *B.1* — the declared type is `float | None`, and the runtime value is always
  `float` or `None`.
- *B.2* — the written value equals the declared derivation applied to the
  current observation, across the controller's exercised decisions.
- *B.3* — no BOHS write, and no branch deciding whether to write, reads any
  BOHS field or any other retained controller state.
- *B.4* — no BOHS field holds a value written before the immediately preceding
  decision.
- *B.5* — at most one write per `act()` call, and no writer outside the
  controller.
- *B.6 and E* — the complete reader set matches the declared readers; no
  environment or evaluator read; no action-selection branch reads a field
  classified as diagnostic.
- *B.7* — the field is `None` after `reset()` and after every declared
  clearing point.
- *B.8* — BOHS-specific thresholds are `Final`, and no threshold changes
  across a run.
- *B.9* — the field's value is traceable to the controller's own observation
  contract only.

**These tests do not exist yet, and neither does the registry.** Until both
exist and pass, the boundary in this ADR is written down, not enforced, and
this document must not be cited as evidence that it is mechanically
guaranteed. Building them is in scope for PR #38, which introduces the first
BOHS controller: that PR needs a class registration entry, a manifest row, the
diagnostic classification of `_last_decision`, and these checks — not only the
docstring correction previously identified.

### E. Diagnostic-only state is outside the budget

State that exists solely to record what a controller did — a decision trace, a
counter for reporting — is outside BOHS and consumes no budget, on one
condition: **no action-selection branch reads it.** The condition is the whole
distinction. A diagnostic field that any action-selection branch reads is
causal state and consumes budget regardless of what it is named.

This carve-out is required for correctness, not convenience: PR #38 adds
`_last_decision` to the base `StationB50Controller` as instrumentation, and an
exclusion that banned all added retained state would prohibit it.

### F. Pre-existing retained state

The following already persists between decisions in `StationB50TrendController`
and its base class. This ADR neither authorises, re-authorises, modifies, nor
extends any of it; each is listed with the source that does govern it.

- **`_mode`** (`EXPLORE`/`SEEK`/`CHARGE`) — causal, observation-dependent. The
  three-mode form including `CHARGE` is EXP-003's, governed by the EXP-003
  specification and ADR 0008. ADR 0004 governs only the earlier two-mode
  EXPLORE/SEEK_RESOURCE hysteresis it decided for EXP-000; it is not the
  authority for `CHARGE`.
- **`StochasticPersistentExplorer` segment counters**
  (`_forward_actions_remaining`, `_turn_action`, `_turn_actions_remaining`) —
  causal. The run-and-turn primitive is specified in EXP-001; ADR 0004 decided
  persistent exploration for EXP-000.
- **`policy_rng`** — causal. A `np.random.Generator` whose bit-generator state
  advances on every run-length sample. It is the largest retained object in the
  controller and is governed by the experiments' seed and RNG-stream
  conventions.
- **`_last_decision`** — diagnostic only, no action-selection reads. It is
  **not** pre-existing merged state: `EXP003ControllerDecision` and
  `_last_decision` are absent from `src/aweform/exp003.py` at base `44f44d4`
  and are introduced by PR #38. It is listed here as retained state of the
  controller under review, not as inherited state, and it is outside the budget
  under Section E.

### G. Exclusions

Outside V0.2 and requiring their own deferral-claiming ADR:

- any additional **causal** temporal or action-path state beyond the BOHS
  budget, whether or not it is observation-derived;
- retention over more than one decision; any accumulation, integration,
  smoothing, filtering, or arithmetic combination of observations;
- any BOHS write, or any branch deciding whether to write, that reads a BOHS
  field or other retained controller state — the cross-coupling channel
  described in B.3;
- any state surviving `reset()`, an episode, a seed, or a run;
- learned or adaptive regulation, update rules, or experience-adjusted
  thresholds;
- episodic, spatial, or map-like memory, world models, or prediction;
- cross-episode persistence or individuality.

Learning, cross-episode persistence, spatial maps, and adaptive updates are
**not** bundled into "memory-capable". V0.2 authorises bounded within-episode
observation history and nothing else; experience-dependent regulation remains
governed by the separate learning-transition ADR named in the research roadmap.

This ADR authorises mechanism only. It authorises no experimental claim, seed
reservation, calibration, or confirmatory run.

### H. First V0.2 experiment, and the status of existing evidence

EXP-004 is the first V0.2 experiment. Its protocol document remains
unwritten and is not fixed by this ADR.

PR #38's controller work is **disclosed preparatory development**, not V0.2
evidence, and is not retroactively relabelled by this ADR. The `18141–18180`
development batch, run under the earlier scope, remains exploratory and
disclosed as such; it cannot be promoted into calibration or confirmatory
evidence.

Reports on `STATION_B50_TREND` must describe it as a controller carrying
bounded one-step observation-history state, so that any difference against
`STATION_B50` is attributed to that addition rather than presented as an
unexplained improvement.

## Rationale

Opening a stage rather than editing ADR 0001 is the better instrument for the
reason ADR 0001 itself gives: the non-goals are deferrals, and the document
already anticipated a later problem claiming one. Editing the list in place
would have rewritten the scope record of four completed experiments to
authorise a fifth. The earlier draft of this ADR did exactly that, and it was
wrong.

The category form is broader than the evidence. Exactly one BOHS value exists,
in one controller; this ADR authorises a class. That is a deliberate decision
by Flow. With the budget at one, the cost is not unreviewed combinations within
a controller — those remain impossible — but that any number of future
controllers may adopt the mechanism without an individual authorisation for
each. The bounds in Section B and the registration gate in Section D exist to
make that cost bounded and visible rather than open-ended.

Conditions B.2 and B.3 do the work a count cannot, and both came from
independent review rather than from this document's author. A budget of "N
scalars" is not a bound on information. An unconstrained derivation packs
arbitrarily much history into one double, which B.2 answers by restricting
every value to a copy or a selection over a single observation. And a set of
individually one-step fields is not a one-step system: cross-coupled
selections preserve bits indefinitely while every single write remains a legal
one-observation selection, which B.3 answers by forbidding any write, or any
decision to write, from reading retained state. Either condition alone leaves
the boundary open.

## Consequences and trade-offs

Every current-scope document that asserts V0.1 must change with this ADR, or
the repository contradicts itself. `AGENTS.md`, `README.md`, the research
roadmap, and `docs/safety-boundary.md` are updated in the same change. A merged
ADR alone cannot make the repository V0.2.

Neither the registry nor the checks exist. Until both do, the strongest true
statement is that the boundary is written down, not that it is enforced — and
because Section D gates merging rather than confirmation, building them is
blocking work for PR #38 rather than deferred work.

Adding observation-history state makes a controller harder to reason about than
one without it: behaviour depends on clearing points, so experiments must pin
the exact source revision, thresholds, clearing points, and state semantics
they inherited rather than tracking a branch.

"V0.1 has no memory" remains true as a statement about the V0.1 stage, and is
the reason for opening a stage rather than amending one. It was never true in
the stronger sense that V0.1 controllers retained nothing; anyone citing it
should mean the narrow boundary defined in the Context above.
